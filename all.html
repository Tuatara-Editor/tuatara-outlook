outlook Manual

for Tuatara 0.90.38 and later, every chapter on one page

This manual is written with modal editing on, first and foremost. Where a command also has a key that works with modal editing off, it is given as well, as the non-modal key.

What outlook is

A package that reads Outlook items, saved mail and Outlook mailboxes as messages, and never changes them.

It is made for examining mail from evidence. Nothing in a message is run. An attachment is opened only when you ask, and from a private copy. The files read are never written to.

1.1 What it reads

Once the package is loaded, opening one of these files shows it as a message, or as a list of messages:

FileShown as
.msg (an Outlook item)the message: its headers, text and
attachments
.eml (a saved mail)the message, its parts read as MIME
.pst, .ost (an Outlook mailbox)its folders, and under each its
messages, a line each: when sent, from
whom, how many attachments, the
subject

Rimu's preview shows them too. M-x check-health says what reads them here, and whether the program that draws a message as it looks (WeasyPrint) is found.

1.2 How it keeps a file safe

A mailbox is read by the package itself, never by another program. The reader runs in a Tuatara of its own, shut in by Tuatara's sandbox (bubblewrap, bwrap), as every program that reads a file from outside does. It sees the mailbox, read only, and the directory it writes the messages in, and nothing else: no home directory, no network. Without the sandbox no mailbox is read.

A message is drawn as it looks by WeasyPrint, also shut in the sandbox, with no network, so nothing is fetched from the internet and the sender cannot learn that the message was opened. An attachment opens in Tuatara, from a copy only you can read, unless you ask for the desktop's own program (chapter 2).

1.3 Where things are kept

  • The messages written of a mailbox go to Tuatara's cache directory (chapter 3).
  • Your labels go to Tuatara's state directory, never near the mailbox (chapter 5).
  • Messages and mailboxes you copy out go where you say, never into an evidence directory (chapter 6).

1.4 The parts of this manual

Chapter 2 is the message: its keys, its attachments, how it looks. Chapter 3 is the mailbox and how it is read. Chapters 4 and 5 narrow a mailbox's list by a search, a field or a label. Chapter 6 copies messages out. Chapter 7 gives the settings and limits, and chapter 8 lists every command and setting.

1.5 Keys

The commands of outlook have keys of their own and, as every package's do, a prefix of their own, C-c o. The keys are in the chapter of each part. Chapter 8 has them all.

2.2 Attachments

RET on an attachment opens it in Tuatara from a copy only you can read. Nothing in it is run.

O opens it in the desktop's own program for its kind, after asking. The copy is private to you, and only a kind that may be opened outside Tuatara is opened: a picture, a PDF, a sound, a video or an Office document. That program is not shut in the sandbox.

A part that cannot be read (an attachment, a value) is said so in the message, in lines that Reading note shows when the message is opened. An attachment whose contents are missing is a short text of that name saying so.

A message attached to a message is shown as a message. How many levels deep this goes is set by *outlook-nesting-limit*; deeper ones are listed as not read. A message and the messages attached to it and to those are limited to 256, so that a small file cannot make the reader take memory or time without end.

2.3 Seeing a message as it looks

P in a message draws it as a mail program shows it. Its HTML is laid out as on a screen, with its colours, tables and fonts and the pictures it carries in their places. Above it are its headers (from, to, subject, dates, attachments) as a mail program prints them, and its internet headers, whole as they came, are on a page of their own after it. The pages are shown in Tuatara's PDF view, with its keys (zoom, search, the text).

The HTML comes from the message itself: the HTML part of a saved mail, an Outlook item's HTML, or the HTML its rich text keeps. A message of plain text alone looks as it is shown already.

It is drawn by WeasyPrint, shut in Tuatara's sandbox with no network, so nothing is fetched from the internet (a picture, a style, a tracking pixel). The line over the pages says how many such things the message holds. WeasyPrint runs no scripts at all. It sees only the message's HTML and the pictures it shows, written into a directory of your cache only you can read, and your fonts, read only.

The program is named by *outlook-page-program*. The pages need poppler's pdftoppm too, as any PDF does. The packages that provide WeasyPrint are: weasyprint on Fedora, Debian and Ubuntu, python-weasyprint on Arch and python3-weasyprint on openSUSE.

2.4 Attachments earlier in a conversation

A reply or a forward quotes the earlier mails of its conversation but seldom carries their attachments. When the mailbox holds those earlier mails, a message opened from its list ends with "Attachments earlier in this conversation". Each attachment is shown under the subject, sender and date of the message it came with, and how it was found (by In-Reply-To, by References, or by the conversation index of the header or of the Outlook item). It says too when one Message-ID is given to several messages. RET on one opens it as the message's own attachments open, from a copy only you can read, shut in the sandbox, nothing in it run.

The earlier mails are found by the Message-IDs the message's In-Reply-To and References headers name, and theirs in turn. When those find none, they are found by Outlook's conversation index (the Thread-Index header, or the PR_CONVERSATION_INDEX of the Outlook item). Its first 22 octets name the conversation and each reply adds 5, so a message whose index is the start of this one's is earlier in the same conversation. The links are read as the mailbox is listed and looked up in tables made once. Reading the earlier mails is part of reading the message, in the background.

In the Enron sample mailbox (71 messages) every message has a conversation index, none has In-Reply-To or References, and two find an earlier message.

Mailboxes

How a mailbox is read, listed, kept in the cache and opened.

3.1 What is read

A mailbox is read by the package itself, as Microsoft's MS-PST lays it out: the Unicode format of Outlook 2003 and later (.pst, and the offline .ost of Outlook 2003 to 2010) and the ANSI format of Outlook 97 to 2002, its blocks as they are, permuted or cyclic.

The offline mailboxes of Outlook 2013 and later (.ost of pages of 4 KB, their blocks compressed) are not described by MS-PST. Such a mailbox is refused, and the refusal says so.

3.2 How it is read

A mailbox is read where it is, a block at a time, never whole, however large it is, and never in the editor. The package's reader runs in a Tuatara of its own shut in by Tuatara's sandbox. There it sees the mailbox, read only, and the directory it writes the messages in, and nothing else. The editor reads only the messages written. The mailbox itself is never written to, nor its access time changed. Without the sandbox (bwrap), no mailbox is read.

The messages are written to your cache directory, each twice: as saved mail and as an Outlook item holding every property the mailbox gives it, so that they can be copied out as either. A contact is written as a vCard (.vcf). An appointment, a task or a journal entry is written as iCalendar (.ics). A distribution list, a note and any other item is written as a message.

A damaged mailbox is read as far as it can be. Every offset and size is checked, and every tree of the file is followed with each part seen once, so that reading it ends. Nothing in it is run.

A message is read with no more than an eighth of the reader's memory, and never more than *outlook-largest-file* of its file, a part it names again and again counted each time. Its text and the attachments read by then are kept, and what is past them is said in the message.

readpst, which read mailboxes before, left out without a word a message of more than about 440 properties, and distribution lists. Both are listed now.

On a mailbox of 20,000 messages (340 MB), the package reads and writes its messages in 5.3 seconds where readpst took 4.8, and lists what it wrote in 8.8 seconds where listing readpst's took 9.6.

3.3 Nothing is left out without a word

  • A message that cannot be read is listed as one, saying why: "(could not be read) Message 200084 of the mailbox could not be read: block 1a4 is not in the blocks' B-tree".
  • A part of a message that cannot be read is said so in the message.
  • What was found wrong in the mailbox as a whole (a check, CRC, that does not match, a page of its B-trees that cannot be read) is said above the list.
  • Messages whose folder is not in the mailbox, or lies more than 64 folders deep, are listed under Orphans. Those of folders outside the top of the personal folders are under Outside the top folder.
  • Deleted items are listed with the others while *outlook-include-deleted* says so.
  • Two folders in one folder whose names are alike, or alike but for case, are told apart by (2), (3) after the name, as is a folder named as a file the reader writes beside it. A folder whose path would pass 1,024 octets has its name cut to fit, and the list shows its path whole.
  • Should the reader stop part way (it failed, or ran out of memory), what it wrote by then is listed, and the list says where it stopped and why. It says too when fewer files are there to be listed than the reader wrote.

3.4 A mailbox from outside

A mailbox in your downloads, on a removable drive, or in another of Tuatara's untrusted directories is listed as well when it is opened safely. It is refused when another file was put in the mailbox's place after it was opened.

The mailbox is opened once. The file summed is the very file the reader reads, whatever is put at its path meanwhile, and a mailbox that changes while it is read is refused. A message or an Outlook item from outside opens as its text, as Tuatara itself reads those.

3.5 The cache

What was written of a mailbox is kept in Tuatara's cache after the list is closed. It is found again by the mailbox's SHA-256 sum and the options it was read with (*outlook-include-deleted*). Opening the same mailbox again, from this computer or from a server, sums it and lists it from what was kept, without reading it again.

It is cleared as Tuatara clears every entry of its cache: *cache-keep* after it was last used, one day as standard, never while the list is open, never when pinned. M-x cache-manager shows it under "Mailboxes read", where RET lists it again, P pins it and d, x delete it. What readpst wrote in earlier versions is not used: such a mailbox is read anew.

A mailbox on a server is read from the copy Tuatara fetched, checked before and after to be as it was fetched. No second copy is made, and none of a mailbox on this computer either, which is checked before and after to be as it was summed. This needs Tuatara 0.90.38 or later.

Searching and filtering a mailbox

Narrowing a mailbox's list to the messages you want.

4.1 The filters

A list can be narrowed by any number of filters, and they stack: each narrows what the ones before it left. A search kept with RET, a field and a label are all filters. The list's first line says by what it is narrowed and how many items are left.

KeyWhat it does

to the messages whose headers or contents match.
RET keeps the pattern as a filter, C-g lets the
one typed go.
C-x / fKeeps the messages one field of which a pattern
matches.
C-x / hHides the messages one field of which a pattern
matches.
LNarrows the list to the messages carrying a label
(chapter 5).
C-x / lLists the filters, each with how many items it
leaves. There d takes away the filter on the line
and D all of them. The later filters are worked
out again.
C-x / rTakes every filter away: the whole list again.

RET on a message of the narrowed list opens it with the filters' matches lit.

4.2 Searching

C-s (or C-r) in a mailbox's list does not move through its lines. It narrows the list, as the pattern is typed, to the messages it matches.

A message matches when the pattern, a regular expression, is found in any of its headers (all of them, not only those the list shows: ^X-Mailer:.*Outlook, ^Received:.*203\.0\.113), in the text of any of its text parts, or in an attachment's name. Text is decoded from base64 or quoted-printable and from its charset, and HTML is searched as its text. Messages attached to it are looked through alike. Case is ignored while the pattern has no capital letter. M-r switches to literal text.

RET keeps the pattern as a filter. The next C-s narrows what that filter left, so invoice then ^from:.*acme leaves the messages that have both. C-g lets go only the pattern being typed.

The text searched is made once, as the mailbox is listed: for each message, in the list's own private directory, deleted with it. Matching runs in the background, the mode line saying how far it has got, and starts again as the pattern changes. The editor goes on meanwhile, however large the mailbox.

Of a message larger than *outlook-search-text-limit* only that much is searched, and of one larger than *outlook-largest-file* only its headers. The list says how many such messages there are. Nothing in a message is run, attachments other than text are never decoded, and the mailbox and what was written of it are never changed.

4.3 Filtering by a field

C-x / f keeps the messages one field of which a pattern matches, and C-x / h hides them. It asks for the field first, the names completed from those found in the mailbox as it was listed:

  • from, to, cc, bcc, subject, date, attachment name (an attachment's name) and your label, first;
  • then every other header its messages have (received, message-id, in-reply-to, references, reply-to, return-path, x-mailer, x-originating-ip and the rest);
  • and what the Outlook item written of each message says of itself, named outlook, a space and the name Microsoft gives the property: outlook importance, outlook sensitivity, outlook message-class, outlook client-submit-time, outlook message-delivery-time, outlook message-flags, outlook conversation-topic, outlook conversation-index, outlook sender-name, outlook sender-address-type, outlook sender-email-address, outlook sent-representing-name, outlook display-to, outlook entry-id, outlook creation-time and so on. Its named properties are given by what they stand for, outlook Keywords, or, named by a number, by the property set's word and the number, outlook address-8083.

The question names beside each whether it is a header or one of these. The names Tuatara makes up hold a space, which no header's name may, so a header such as Attachment: or Label: in a message stays a header and never poses as one of them. A line whose name holds a space is no header and is not offered.

Then it asks for the pattern: a regular expression, or literal text after M-r, exactly as Tuatara's search reads it. It is tried on that field's values alone. A message with a header many times (received) is kept when any of them matches. A message without the field is not kept by C-x / f, and not hidden by C-x / h.

The filter stacks with the others and is listed by C-x / l. Opening a message the list was narrowed to lights the header lines that matched, from the header's name to the match.

A pattern used often can be saved under a name with Tuatara's M-x save-named-pattern (a regular expression, or literal text after M-r, remembered as either) and given later as [[:name:]] in any pattern.

5.2 Where labels are kept

The labels are kept for you alone in Tuatara's state directory (~/.local/state/tuatara/outlook/labels/ unless XDG_STATE_HOME says otherwise), never in the mailbox nor beside it. A file is named by the mailbox's SHA-256 sum. Whenever that mailbox is opened again, a copy of it too, its labels come back, and a mailbox changed in any way starts with none. Nothing is written near the mailbox. The words above a mailbox's list say where its labels are kept.

A message is known by its folder, its Message-ID and the SHA-256 sum of its headers as they were written. Two messages of a folder alike in all three (a Message-ID forged or copied, headers alike) are told apart by their order. The numbers its files are given are not used: they follow the order of the folder and change when deleted items are read or left out.

Each change is a line added to the end of the mailbox's labels file, in one write while holding the file's lock, so two sessions labelling the same mailbox lose nothing of each other's. The file is read from the first line, and written again with only the labels it leaves once it has grown long.

A line beginning @ in each labels file says which mailbox it is for: its file's name, the path it was last opened from, its size, its SHA-256 sum and when its labels last changed. A file from before it existed still reads, and is given the line the next time its mailbox is opened.

Labels put on when readpst read mailboxes were kept under the headers readpst wrote, which the package writes otherwise. They stay in the labels file, and the label manager shows them, but they show on no message read now.

5.3 The label manager

M-x outlook-label-manager, or M (C-c o m) in a mailbox's list, lists every mailbox that has labels, one section each: its file's name, the path it was last opened from, whether the file is there now, the start of its SHA-256 sum, how many labels and messages, and when they last changed. A mailbox read with its deleted items has a section of its own. Under it is each label with the number of messages that carry it. The heading says where the labels are kept and how much room they take.

Copying messages out

Messages from a mailbox as files, as one mbox file, or as a new mailbox.

Marks stay on messages a filter hides, and C copies them too. The question names how many it copies.

Copying runs in the background. The message line then says how many were copied and which could not be.

6.2 Files, one for each message

e writes internet mail as it was written of the mailbox. m writes the Outlook item from the mailbox itself, beside each .eml, every property kept.

A copy is named by when the message was sent and its subject, as in 2026-04-30 0915 kea survey.msg. A name already taken gets (2), (3) and so on, and nothing in the directory is overwritten. Characters a name cannot hold on other systems' drives (: * ? " < > | / \) are left out or made -.

6.3 One mbox file

b collects the messages into one mbox file, the format most mail programs import. Each message is as it was written, after a From = line with its sender's address and when it was sent. A line of a message beginning with =From = (after any number of =>) is written with one > more, as the mboxrd form does, so that reading it back gives each message as it was.

It asks for the file. A name taken gets (2), (3) and so on, and nothing is overwritten. It is written in the background, and a copy stopped half-way is deleted. Contacts and appointments are left out.

6.4 A new Outlook mailbox

p writes the messages into a new Outlook mailbox (.pst), in the folders they are listed in, below its top folder. It asks for the file. .pst is added to a name without it, a name taken gets (2), (3) and so on, and nothing is overwritten. It is written in the background, a file stopped half-way deleted, and never in an evidence directory. Contacts and appointments are left out.

Each message is written from the Outlook item written of it as the mailbox was read: every property, recipient and attachment the mailbox gave it, a message attached to it with its own, and its named properties (Outlook's categories, a contact's addresses, an appointment's times and the rest) with what they stand for, given numbers of the new mailbox's own.

The mailbox is written as Microsoft's MS-PST lays out the Unicode format Outlook 2003 and later read. Its strings are in Unicode, its data blocks are encoded as Outlook encodes them (the permutation of MS-PST section 5.1), and every block and page has its check. The folders and tables Outlook needs to open it are there too (the top of the personal folders, deleted items and the search folders).

A mailbox may be as large as 50 GB, the most Outlook takes as it is installed. The maps of which parts of the file are taken are written where MS-PST puts them, however far the file goes (each allocation map, page map, free map and free page map), and the file is streamed to the drive as it is made. Read back, by the package and by libpff, the messages copied out come out as they went in: their headers, text, HTML and attachments alike.

Settings and limits

How much of a file outlook reads, and what it leaves unread.

outlook reads files from anywhere, some made to do harm. Everything it reads is held to a size or a time, so that no file can make it run without end or fill the memory. What it leaves unread, it says in the list or the message.

7.1 The settings

Set them in the package's :config in your init file:

(load-package "outlook"
              :source "https://github.com/Tuatara-Editor/tuatara-outlook"
              :config
              (setf *outlook-include-deleted* nil))

C-h v on a setting shows its help once the package is loaded. A size is a whole number of octets, or words such as 512M or 64G, in units of 1024. A time is a number of seconds, or words such as 90m or 2h.

7.2 Fixed limits

These are not settings:

  • a message is read with no more than an eighth of the reader's memory;
  • at most 256 messages attached to a message and to those;
  • a message of parts within parts is read as deep as twice *outlook-nesting-limit*;
  • folders more than 64 deep are listed under Orphans;
  • a folder whose path would pass 1,024 octets has its name cut.

7.3 What outlook does not do

  • It does not read the offline mailboxes of Outlook 2013 and later (.ost of pages of 4 KB, blocks compressed). It refuses them and says so.
  • It does not read a mailbox without the sandbox (bwrap).
  • It never changes a mailbox, an item or a saved mail, or its access time.
  • It does not fetch anything a message points to, and runs nothing in it.

Every command and setting

Each command and setting of outlook, to look one up by name.

The tables are made from the program each time this manual is made, so they never list a command or setting that outlook does not have. The first table has four columns. The first two are keys: the modal keys, which work only with modal editing on, and the non-modal keys, which work with it off too. A command with no key says M-x and its name in the second column, because you can only run it by its name. The third column is the name of the command and the fourth says what it does.

To run a command by its name, press M-x, type a few letters of the name and press RET. To find a command from within the editor, press C-h f. To find the command that a key runs, press C-h k and then the key. The editor's own settings and commands are in chapters 21 and 22 of its manual.
